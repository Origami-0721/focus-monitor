# focus-monitor

用笔记本前置摄像头 + Windows 前台窗口，长期记录你的专注状态，并分析**你几点最容易进入心流**。

不是番茄钟，不是时间统计软件。它想回答的是：**我什么时段、什么条件下能最快进入状态、能撑多久。**

## 功能

- **双路判定**：摄像头看"人在不在、看没看屏幕"，Win32 API 看"在用什么软件"。缺一路都判不准
- **六种状态**：专注 / 中性 / 伏案 / 走神 / 疲劳 / 离开
- **前台托盘常驻**：开机自启，无窗口，改配置不用改代码；托盘菜单直接显示当前状态和今日累计投入喵
- **应用窗口**：面板、评分、报告都在程序自己的窗口里（系统 WebView2 渲染，不用开浏览器），跟随系统深浅色主题；点窗口 × = 最小化到托盘喵
- **规律报告**：会话切分、心流片段、黄金时段排行；另有近 14 天每日投入柱状图、平均每天的小时节律、CSV 原始数据导出喵
- **全程本地**：不保存任何图像、不联网上传

## 工作原理

### 三路视觉信号

| 信号 | 做法 |
|---|---|
| 头部朝向 | MediaPipe FaceLandmarker 取 6 个关键点，`solvePnP` 解出鼻尖在相机坐标系的方向角 |
| 眼睛闭合 | 眼睛纵横比 EAR，持续低于阈值判疲劳 |
| 眨眼 / 揉眼 | 同一个 EAR 数眨眼次数（不含眯眼、只算正对屏幕时完成的）；Pose 的手腕点近似"手在眼周"。**产出不进状态机** —— 它判的是视疲劳（该歇眼睛了），不是困，详见 `使用教程.md` |
| 坐姿 | PoseLandmarker 肩线倾角 + 人脸尺度变化（是否越凑越近） |

> 头部姿态没有用欧拉角分解。实测那套公式在俯仰上会整体翻转 180°（中位数 171.7°），
> 改用鼻尖方向角 `atan2(ty, tz)`——对 3D 模型尺寸不敏感，稳得多。

### 状态机

```
离开   ← 键鼠空闲 / 人脸消失 超过阈值
疲劳   ← 持续闭眼
专注   ← 看着屏幕 + 工作应用
中性   ← 看着屏幕 + 其他应用
伏案   ← 低头对桌子（看书/写作业）
走神   ← 没在看屏幕（转头/低头过狠），或在一分钟内来回切了太多次窗口
```

### 走神只看"人"，不看"应用"

**应用类型永远不会单独判走神。** 早期版本会把标题里带「哔哩哔哩」的窗口直接判成走神，
于是"在 B 站看半小时高数课"也被记成走神 —— 实测报上来的 bug。平台是娱乐的，
内容不是，而程序只看得到进程名和标题、看不到内容，所以它没有资格下这个结论。

现在走神只剩两条**行为**判据：

1. **没在看屏幕** —— 转头或低头过狠（`YAW_TOL` / `DESK_PITCH_MAX`）；
2. **来回切窗口** —— 一分钟内换了太多次前台窗口（`DISTRACT_SWITCH_RATE`，默认 20 次）。
   阈值是拿真实数据标定的，觉得抓不住就调小、觉得误伤就调大，调到 9999 等于关掉。

应用分类降级成"只抬高、不贬低"：`WORK_APPS` 里的能升成**专注**，其余（含娱乐应用、
不认识的）一律是**中性** —— 而中性是算进投入时长的。`DISTRACT_KEYWORDS` 命中的
只是"不硬说专注"，不再扣分；`STUDY_KEYWORDS` 命中的直接升成专注。

报告仍然把走神拆成 **应用导致的** 和 **人没看屏幕** 两部分，但现在的"应用导致"
指的是上面第 2 条那种来回切换，而不是"你打开了某个应用"。

## 安装

需要 Windows 和一个前置摄像头。

**不想折腾环境**：去 [Releases 页面](https://github.com/Origami-0721/focus-monitor/releases) 下载最新版 zip，
解压后打开 `focus-monitor` 文件夹，双击里面的 `focus-monitor.exe` 就能用喵 —— 不需要装 Python，也不需要命令行，
数据（focus.db、日志、报告、CSV）都会存在 exe 所在的文件夹里，怎么都不会丢喵。

想从源码跑：

```powershell
uv run focus.py --selftest        # 自检，不开摄像头
uv run focus.py                   # 开始监视（托盘图标）
```

首次运行会自动下载两个 MediaPipe 模型（约 11MB）。

> 依赖要求在 `pyproject.toml` 里锁了 `>=3.11,<3.13`。MediaPipe 目前没有 3.13+ 的 wheel，
> 用 uv 会自动拉一个兼容的解释器。
>
> 这两个版本不是写着好看的：`.github/workflows/selftest.yml` 每次 push 都会在 Windows 上
> 分别用 3.11 和 3.12 各跑一遍「全部模块语法检查 + 自检 + 冒烟测试 + 管线冒烟 + 变异测试
> + 冒烟变异测试」，任何一个红都说明声明的支持范围是假的。CI 还故意把控制台编码钉在
> 西文代码页上跑 —— 中文提示在 GBK 控制台下看不出问题，只有换到西文代码页才会暴露
> （详见 `focus.use_safe_console`）。
>
> 「管线冒烟」（`smoke_pipeline.py`）真跑采集循环，一共四个场景：
> ① 恒定喂一张正对屏幕的脸，状态必须判成「专注」—— 前两步测的是"逻辑对不对"和
> "页面渲不渲得出来"，**测不出"根本没人喂数据给逻辑"**，这一条补的就是那个洞
> （起因是一次真实事故，详见该文件开头的说明）；
> ② 脚本化时间线「睁眼 → 闭眼 → 转头出画 → 回来还闭着眼」，确认闭眼计时不会跨过
> 丢脸那段盲区接着累加 —— 会的话，人只是转了下头，回来 1 秒就被记一条「疲劳」；
> ③ 「暂停 → 恢复」，同一条计时不能沿用暂停前的起点。
> ②③ 一起才钉得住"复位要放在重新开始观察的那一侧"—— 只写在其中一支里，
> 另一条路径照样漏。②③ 还都验反面：一直闭着眼时「疲劳」必须照样判得出来，
> 免得修 bug 顺手把功能修没了。
> ④ 「眼睛该歇会儿了」必须真的弹出来。①②③ 问的是"状态判得对不对"，这一条问的是
> **"提醒到底接上了没有"**：阈值函数、眨眼计数全对，但采集循环里那个 if 没接
> `on_eye_break` 的话，功能会静默消失（照算、照显示、不报错、不提醒）。三段：
> 不限间隔时必须弹多次、间隔设成 1 小时时**正好弹 1 次**、阈值配成永远达不到时
> **一次都不弹**。最后那段的用处不是凑数 —— 见下面「冒烟变异测试」。
>
> 「变异测试」（`scripts/mutcheck.py`）问的不是"代码对不对"，而是
> **"前面那几步本身有没有用"**：把每条关键断言对应的实现逐条改坏，
> 自检必须变红。全绿就说明那条断言是摆设 —— 它让人以为这块已经覆盖了，
> 比没有断言更糟。这个坑在本项目里反复出现过（`assert PYW.exists()` 在开发机
> 恒为真、`assert str(PYW) in _lnk` 被写死路径的旧写法同样满足、还有
> 「绿点为什么不见了」那次自检全绿但根本没人喂数据给逻辑）。本地跑：
>
> **自检不许碰真网络。** 这是同一种毛病的另一副面孔，而且它的副作用直接
> 落在用户脸上：`wait_and_open(timeout=0.1)` 那条断言的本意是"服务等不到时
> 要快速返回"，但它用的是**真的 `URL_PATH`（用户机器上就是运行中的应用写下的
> `127.0.0.1:8787`）+ 真的 `urlopen`**。在应用正在运行的机器上"服务等不到"
> 这个前提根本不成立 —— 服务就在那儿，于是自检一路请求到**用户自己的实例**，
> `/show-panel` 把他的窗口 `show()` 出来。断言只看"有没有超过 10 秒"，
> 照样是绿的。用户的原话是「每次让你改一点东西的时候就是这样一直弹出这个在
> 最顶层」：因为"改一点东西"就要跑一遍自检，而每跑一遍自检就弹一次他的窗口。
> 现在那一段会把地址指到没人监听的端口、把 `urlopen` 换成必定失败的假货，
> 并断言"只敲过那个死地址"。
>
> ```powershell
> uv run python scripts/mutcheck.py
> ```
>
> 但它**只管 `--selftest`**，而"提醒到底会不会弹"这件事自检根本测不到 ——
> 那唯一的防线是管线冒烟的场景④。所以场景④ 的断言也有自己的变异闸门
> （`scripts/smoke_mutcheck.py`，本机 100 秒）：
>
> ```powershell
> uv run python scripts/smoke_mutcheck.py
> ```
>
> 这个脚本后来也把**场景①** 收了进来：场景① 那几条断言（视觉链路真的被调用过、
> 真的落了样本、正对屏幕的脸判得出「专注」、ear 真的写进了库）之前一条变异都没有，
> 而它保护的正是"视觉链路断了"那类**真实发生过**的事故 —— 采集循环重构时把
> `read_face` 和缓冲区填充整段删了，**自检全绿**（因为自检测的是 `decide()` 本身）。
> 现在它按变异各自指定场景：打 `focus.py` 的跑场景④，打 `smoke_pipeline.py`
> 的跑场景①，谁也不替谁白等。
>
> 这个脚本是**被自己打脸打出来的**：场景④ 里那段"反例"（阈值配成 1e9，本该
> 一次都不弹）写完看着很稳妥，直到拿"阈值写死成 0.4 秒"这条变异去试 ——
> 前两段照样过，只有反例抓得住它。也就是说，在造出那条变异之前，
> **那个反例从来没起过作用**。永远不会失败的安全网和永远不会失败的断言
> 是同一个毛病。
>
> **它后来又被打脸一次（CI #36）**：反例的时长原来只有 3.0 秒，本机节拍 1.0 秒
> 时刚好只弹 1 次、勉强抓住那条变异；CI 的 3.12 runner 稍慢，只跑到一次结算，
> 变异就**逃逸**了 —— 同一个提交的 3.11 job 全绿，只有一边红。根因是采集循环
> **第一次结算的 `eye_run` 恒为 0**（`eyes_since` 在那一拍才置位），所以"弹"
> 至少要跑到第二次结算。现在反例跑 6.0 秒。教训：**反例的"安静时长"不能抠到
> 只剩一次余量** —— 它越该安静，越容易在慢机器上退化成"什么都不发生"。
>
> 「判据回放」（`scripts/replay_decide.py`）补的是上面几步都覆盖不到的一类问题：
> **阈值调错是静默的**。自检只能证明"函数本身符合预期"，证明不了"换到真实数据上
> 分布会怎么偏"——没有任何报错，状态分布整体偏移，自检全绿。实测被抓过一次：
> 旧的"按应用类型直接判走神"把 **68.5%** 的走神样本判错了（在 B 站看高数课被判成
> 走神），而自检完全覆盖不到。改 `decide()` 或 `DISTRACT_SWITCH_RATE` / `YAW_TOL` /
> `PITCH_TOL` 之后跑一遍，对着输出确认两件事：「由走神变回来的」是不是他真正在学的
> 东西，「新判出来的走神」是不是确实像在走神：
>
> ```powershell
> uv run python scripts/replay_decide.py --db <你的 focus.db>
> ```
>
> **它只读。** 库先经 `sqlite3.backup()` 拷到临时目录再读 —— WAL 模式下直接复制
> 主文件会丢掉最近的写入，拿一份"看起来正常"的旧数据算出错误结论。

## 使用

> **第一次用请看 [使用教程](使用教程.md)** —— 按「第一天 → 日常 → 两周后」的顺序
> 讲怎么上手、怎么看报告、什么时候才该动阈值。下面是命令速查。

```powershell
uv run focus.py                    # 托盘常驻（图标在任务栏的 ^ 折叠区里）
uv run focus.py --dashboard        # 只起面板服务（窗口版用托盘打开即可，无需此参数）
uv run focus.py --report           # 生成 HTML 报告并打开
uv run focus.py --install-startup  # 装开机自启
uv run focus.py --selftest         # 跑自检
uv run focus.py --backup           # 备份 focus.db（监视运行中也能安全执行）
uv run focus.py --compact          # 看看有多少旧数据可清理（只预演，不删）
```

生成报告的同时会在同目录写一份 `focus-日期.csv`（UTF-8 BOM + 表头，
Excel 直接双击就能打开），方便自己拿去统计喵。

### 备份与清理磁盘

样本大约 **1 秒 1 行**，一年下来 0.5–1 GB，而且只增不减。所以有两个命令：

```powershell
uv run focus.py --backup                        # 备份 → focus-backup-20260916-132911.db
uv run focus.py --backup --out D:\my-backup.db  # 也可以指定位置（比如移动硬盘）

uv run focus.py --compact                       # 预演：只告诉你"能删多少"，不删
uv run focus.py --compact --days 180 --yes      # 真删 180 天以前，并回收空间
```

`--backup` 用的是 SQLite 的在线备份接口，不是复制文件 —— WAL 模式下
`focus.db` 和 `focus.db-wal` 是两个文件，**单拷 focus.db 会安静地丢掉最近一段
还没合并的样本**（库能打开、能查，只是少一截，最难发现的那种坏法）。
用备份接口取的是事务级一致快照，而且**监视正在跑的时候也能安全执行**，不用先退出。

`--compact` 是**唯一会删数据的操作**，所以设了三道闸门：

1. **默认只预演**。不加 `--yes` 就只打印"要删多少行、什么时间范围"，然后结束。
2. **删之前强制先备份**。备份失败就中止，绝不允许出现"删了但没备份"。
3. 备份路径和删除范围都会打印出来，随时能自己找回。

> **注意**：`--compact` 删掉的原始样本**不会**被聚合成摘要，报告里那段历史就没有了。
> 这是刻意的取舍 —— 报告里每个数字都来自同一条样本序列（`_timed()` 靠相邻样本的
> 时间差算时长，上限 5 秒），把一小时压成一行之后这行只能贡献 5 秒，所有时长统计
> 都会塌掉。要让它进报告就得给报告开第二条数据通路，让每个板块同时读两种口径 ——
> 那是重构级别的改动，不值得为"少一个功能"冒这个险。
> 所以宁可**明确地删**，也不做一个"看起来还在、其实已经失真"的聚合。
> 想全留着就别执行 `--compact`；想自动化就自己挂个计划任务，别让程序替你决定删数据。

### 托盘图标

| 操作 | 效果 |
|---|---|
| **左键单击** | 有待评分 → 直接打开评分页；否则 → 打开面板 |
| 右键 | 菜单：打开面板 / 自述评分 / 生成报告 / 暂停 / 退出 |

菜单最上面两行是只读信息，跟着实时状态走：**当前状态** 和 **今日累计投入**。
不用打开面板就能瞄一眼今天投入了多少喵。

> 系统气泡（提醒打分那个）**点了没反应是正常的** —— pystray 只处理左键和右键，
> 没有接 `NIN_BALLOONUSERCLICK`。所以提醒文案直接写了"点托盘图标"，
> 那才是可靠路径。

### 桌面开关

```powershell
uv run focus.py --install-shortcut
```

会在桌面建一个**「专注监视」**快捷方式，双击即切换开/关：

| 图标 | 状态 |
|---|---|
| 绿点 | 正在记录 |
| 灰底横杠 | 已停止 |

快捷方式的图标是静态的，所以每次切换时脚本会连 `.lnk` 一起重写，Explorer 立刻刷新。
开启时会另起一个游离进程，等面板就绪后**请监视进程把它的窗口显示出来**
（模型加载要十几秒，立刻打开只会看到「无法连接」）。
**这一段默认不做**（见下面的 `AUTO_OPEN_PANEL`）：双击开关只起进程、不弹窗口。

> 这一步必须是"请监视进程显示"，不能让那个游离进程自己去开页面 ——
> 窗口属于监视进程，子进程里没有窗口，它自己开只会走"窗口层不可用"的兜底、
> 用系统浏览器弹一个新网页。早期版本就是这样：每双击一次开关就多一个
> 浏览器标签页，而真正的应用窗口根本没出现（实测报上来的 bug）。

### 配置

打开实时面板 → **设置**。所有阈值、应用分类、行为开关都能在网页上改，**保存后 1 秒内生效，不用重启**，写入 `config.json`。

四个「行为」开关：

- **伏案计入专注时长**（`DESKWORK_IS_ENGAGED`，默认开）
- **启动时自动打开面板**（`AUTO_OPEN_PANEL`，**默认关**）—— 关着的时候双击桌面开关只起进程、不弹窗口；"到底跑起来没有"看桌面开关的绿点。想看面板点托盘图标，那条路不受这个开关管（它管的是"自动"，不是"能不能看"）。首次运行也受它管。
- **到点提醒打分**（`RATE_REMIND`，默认开）—— 就是那个「该打个分了」的托盘气泡。关掉之后**只是不弹气泡**：待评时段照样在攒，点托盘图标照样能打。
- **眼睛该歇会儿了**（`EYE_BREAK_REMIND`，默认开）—— 连续用眼 40 分钟（眨眼率偏低时 25 分钟）后那个托盘气泡。关掉之后同样**只是不弹气泡**：面板里那条提示照旧、日志里也照旧记。

> 两个气泡**故意分成两个开关**，而不是合成一个"静音所有气泡"：该不该响的判据不同。打分提醒的价值是"趁你还记得住"，关掉就真没了；眼睛提醒的价值是"打断你抬头看远处"，而这件事你自己也做得到。合成一个的话，想静音其中一个就得连另一个一起关。

## 分析模型

- **会话**：一次"坐下来用电脑"。样本空档 >2 分钟（待机/关机）或连续离开 >15 分钟，都算会话结束
- **心流**：会话内连续投入 ≥15 分钟，**允许中间有 ≤60 秒的短暂中断**（挠头、喝水不该掐断记录）
- **进入心流耗时**：从坐下到第一段心流开始。按时段聚合，就是"黄金时段"那张表

黄金时段只统计**累积满 10 分钟**的钟点，避免拿几秒的样本编出"100% 专注"的假排名。

## 报告的图表

报告里的柱状图全部是内联 CSS + SVG 画出来的，没有引任何图表库，所以报告始终是**单文件 HTML**，拷走就能看喵。

- **应用使用记录**：列出**所有**用过的应用，含时长、占活跃比、出现时段、主要状态。不只是专注和分心 —— 中性时间（查资料、翻文件、写文档）也在这里，否则会觉得"记录少了一大块"
- **近 14 天每日投入**：每天一根柱，悬停看当天投入时长和专注率。只显示有记录的自然日
- **全天活跃分布**：按「平均每天」归一化 —— 只有部分天用电脑的钟点不会被少有的几天撑虚高，看的是作息节律而不是总量喵
- **黄金时段 / 状态分布 / 时间轴**：沿用原有分析，排行和结论不受归一化影响

## 校准（首次使用请读这一节）

默认阈值是"大多数人"的取值，不一定适合你的脸型、摄像头位置和光照。
**头一两周的数据请当成校准期，不要直接拿去下结论。**

> **先说清楚：程序里没有单独的「校准」功能。**
> 这里的"校准"是一个**时期**，不是一个要你去点的界面 —— EAR 基线是自动学的，
> 你不需要做任何操作。真正需要你动手的只有一种情况（见下面「怎么看自己需不需要调」），
> 那时候改的是 **主窗口 → 设置 → 判定阈值** 里的字段，没有别的地方。

### 眼睛闭合（EAR）—— 唯一需要你动手的一项

EAR 全称纵横比，就是"眼睛睁开的高度 ÷ 宽度"。这个比值跟脸型强相关，
硬件默认值在别人脸上可能是"睁眼"，在你脸上就成"闭眼"了。

好消息是它**会自己学**：程序滚动保留你最近一段时间的 EAR，
取 75 分位当作"你的睁眼基线"，再乘以系数当阈值。所以只要你正常用几天，
它自己就贴合了。学习进度在实时面板上直接写出来：

```
睁眼基线 0.312 · 已自适应        ← 学好了
睁眼基线学习中 37/60              ← 还没攒够样本
```

（分母是 `focus.EAR_MIN_SAMPLES`，当前 60，不是 300。）

看到"睁眼基线学习中"是正常的，不是坏了。这段时间疲劳判定可能偏松或偏严，忽略就好。
面板上**不会**出现"校准"两个字 —— 没有这个操作。

### 怎么看自己需不需要调

工具自带的验证方式就是**自述对照**（见下一节）。如果评了几十块之后发现
相关系数一直低于 0.4，说明测量和你的感受系统性对不上，这时候才值得去动阈值。

调的顺序建议是：**先动 EAR，再动姿态角**。EAR 影响最大也最好理解。

### 别调的东西

- **不要为了"好看"调高阈值**。把专注判松了，报告数字漂亮了，但数据就废了
- **不要照着别人的配置抄**。阈值是跟硬件和脸绑的，抄过去只会更差

## 自述对照（数据到底准不准）

工具本身只会输出数字，没有任何东西能证明那些数字和你的真实感受对得上。
所以加了一层**自述评分**：每 30 分钟一块，你凭感觉打 1–5 分，然后和实测投入率做相关性。

**一条硬约束**：评分界面**不显示任何实测数据**。要是写着"这段测出 85% 专注"，
你会被那个数字锚定，收集到的就不是独立评价，没法用来验证任何东西。

**什么时候提醒你打分**：只在自然断点。如果检测到你正处在连续投入里（≥5 分钟），
提醒会自动推迟 —— 在人专注正盛的时候弹窗是本末倒置。一直专注就一直不问，
因为那本来就是想要的状态，没什么好打分的。

但"不打扰"有个上限：**连续投入超过 2 小时仍会提醒一次**。纯粹等断点会造成
一个反直觉的偏差 —— 一整个上午连续投入、只在切窗口那几十秒里断一下的人，
几乎没有断点，于是**最专注的那些时段一个评分都收不到**，样本被系统性地
偏向前半天被打断的时段。而相关性验证的恰恰就是"专注"，这个偏差方向最坏。
托盘气泡不抢焦点、不阻塞输入，比"永远收不到训练数据"划算。

相关性会直接印在报告上：

| 相关系数 | 含义 |
|---|---|
| ≥ 0.7 | 测出来的和感受到的是一回事，数据可信 |
| 0.4 – 0.7 | 大方向对得上，阈值还有调的空间 |
| < 0.4 | 对不上，该看阈值了 —— 但样本还少的时候先别动手 |

样本少于 **30** 对时不给结论。门槛定这么高不是保守：拿纯随机数据跑 3000 次
模拟，**8 对**样本下"|r| ≥ 0.4"有 **30.8%** 的概率是假阳性（|r| ≥ 0.7 也有 5.2%），
30 对时才降到 3% 左右。八个点算出来的"中等相关"，三次里有一次纯属噪声 ——
拿它去改阈值，只会把本来正常的判定改坏。

n 刚过门槛时结论后面还会带一句样本量提醒（高相关/中等相关是"这个结论还可能变"，
低相关是"先别急着动阈值，再攒一些评分看看"）。**越是催你动手改阈值的那两条结论，
越需要这句话** —— 它们才是真正会让人跑去动设置的地方，也出自同一个原因。

## 隐私

- 所有处理在本地完成，**不保存任何图像**，不联网上传
- 磁盘上只有 `focus.db` 里的数值指标（角度、时长）和窗口标题
- 实时面板只监听 `127.0.0.1`，不对外网开放
- `.gitignore` 已排除 `focus.db` / `focus-backup-*.db` / `focus.log` / `config.json` —— 提交前请确认

### 导出的 CSV 和 focus.db 一样敏感

`focus.db` 里逐秒记着你**前台窗口的完整标题** —— 打开的文档名、浏览器标签、
聊天窗口联系人都在里面。CSV 导出是同一批数据，只是换了个格式，
**它就是 focus.db，只是更容易被误发出去**。

`--backup` 产出的 `focus-backup-*.db` 同理：它**不是"脱敏的存档"**，
而是 focus.db 的一份完整拷贝，一样敏感。它已经加进 `.gitignore`
（注意 `focus.db` / `focus.db-*` 这两条通配**盖不住** `focus-backup-*.db`，
名字里没有 `focus.db` 这个片段），但备份到网盘或移动硬盘时请自己确认目的地。

所以：

- CSV 已加入 `.gitignore`，但**上传网盘、发群里、贴 issue 前请自己再确认一遍**
- 贴问题截图时，报告页的"应用排行"部分通常也带着窗口标题，注意打码
- 想要干净的复现数据，可以导出一段时间范围再手工删掉 title 列

这不是过度谨慎 —— 窗口标题泄露的信息量比大多数人想的大得多。

## 已知限制

- **分不清"低头看书"和"低头玩手机"**。前置摄像头从正面拍，两者画面几乎一样。伏案是否计入专注时长可在设置里开关
- **看不到驼背**。正面视角拿不到脊柱侧面轮廓，坐姿只用肩线倾角估算，不是医学结论
- **只支持 Windows**。托盘和窗口监视依赖 Win32 API
- **应用分类靠关键词**。游戏 exe 名和中文标题不匹配默认列表时会被静默归到"中性"，需要自己维护关键词表
- 摄像头检测受光照和坐姿影响，阈值需要按自己的环境调
